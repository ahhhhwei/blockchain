# 比特币的密码学原理

比特币主要用到密码学的两个技术，分别是**哈希**和**签名**。

## 一、哈希

- 抗碰撞性 `(collision resistance)`

  碰撞性是指哈希碰撞，哈希碰撞的产生：给定输入的2个值 $x$ 和 $y$，若经过哈希函数运算，使得输出 $H(x)=H(y)$​，此时就产生了哈希碰撞。

  哈希碰撞是很常见的，此时不同的输入会映射到哈希表中的同一个位置，毕竟输入是无穷大的，而输出只是在有限的哈希表中，比如比特币中的哈希函数 `SHA-256`，有2的256次方空间容纳，尽管这个数字相当巨大，但还是比输入(无穷大)小，所以说哈希碰撞是不可避免的。

  而现在所说的抗碰撞性是指：虽然说会产生哈希碰撞，但这种哈希碰撞很难被人为制造，也就是给定一个输入 $m$，哈希运算得到$H(m)$，但是很难人工找到另外一个输入 $m'$，使得2次的哈希结果完全相同，即 $H(m)=H(m')$​​。

  通过上面充分理解抗碰撞性后，得到一个应用，比如防篡改性应用。比如你有一份重要文件，需要上传在云服务器上，上传前对这份文件进行哈希运算并保存结果在本地，过一段时间下载时，为了判断这份文件是否篡改过，只需再一次对这份文件哈希运算，跟上传前的哈希值比较，若相等，则没有篡改，否则篡改过。因为篡改者很难人为的制造篡改后的哈希值跟篡改前的一模一样。

  这里有一个例外是 `MD5` 算法，以前很流行的哈希函数，但是经过实践经验现在已经知道如何去制造 `MD5` 的哈希碰撞。比特币中使用的哈希函数为 `SHA-256`，目前还没有找到哈希碰撞的方法。

- 隐蔽性 `(hiding)`

  隐蔽性也就是哈希函数是单向不可逆性，也就是说一个输入 $x$，可以计算哈希值为 $H(x)$，但通过 $H(x)$, 不能反向计算出这个 $x$，除非暴力破解，也就是一个个去试。所以这个隐蔽性的前提是输入的空间要足够大且输入的取值要分布均匀，若输入的空间已经足够大了，但所有取值只在一小块区间中，这样也是不行的。

- 谜题友好性 `(puzzle friendly)`

  所谓谜题友好性是指，计算的哈希值结果是不可预测的，比如某个输入 $x$，想要哈希值 $H(x)$ 在某个范围内，没有什么捷径可走，只能一个个去尝试这个 $x$。

  这个性质在区块链中有个重要的例子，就是比特币挖矿，也是比特币挖矿的本质。

  在比特币的区块链中，每个区块有一个区块头，区块头中其中的2个域，分别为随机数 `nonce`和目标值 `target`。

  矿工们要做的事情就是不断的尝试这个 `nonce` 值，并将这个 `nonce` 值结合区块头信息一起作为输入，然后计算哈希值。若哈希值小于或等于这个 `target` 值，说明挖矿成功，否则不成功，继续尝试其他 `nonce` 值。 $H(block header + nonce) <= target$
  
  通过上面可知，要想取得某个 `nonce` 值满足上面公式，没有什么捷径可走，只能一个个去尝试，所以只能做大量的工作来验证，这就是所谓的**工作量证明** `POW(proof of work)`，也就是所谓的比特币挖矿。

  虽然说**挖矿的过程很难**，但若挖矿成功后其他矿工**验证其结果很简单**，只需计算一次，看是否满足要求即可。

## 二、签名

**私钥签名，公钥验证签名**

签名过程：

1. `Alice` 用单向散列函数计算消息的散列值。
2. `Alice` 用自己的私钥对散列值进行加密。
   用私钥加密散列值所得到的密文就是 `Alice` 对这条散列值的签名，由于只有 `Alice` 才持有自己的私钥因此除了 `Alice` 以外，其他人是无法生成相同的签名（密文）的。
3. `Alice` 将消息和签名发送给 `Bob`。
4. `Bob` 用 `Alice` 的公钥对收到的签名进行解密
   如果收到的签名确实是用 `Alice` 的私钥进行加密而得到的密文（签名），那么用 `Alice` 的公钥应该能够正确解密，解密的结果应该等于消息的散列值。如果收到的签名不是用 `Alice` 的私钥进行加密而得到的密文，那么就无法用 `Alice` 的公钥正确解密（解密后得到的数据看起来是随机的）。
5. `Bob` 将签名解密后得到的散列值与`Alice`直接发送的消息的散列值进行对比。
   如果两者一致，则签名验证成功；如果两者不一致，则签名验证失败。

## 三、比特币账户

比特币账户实际上就是一个公私钥对（用来签名），可以非常方便的用来签名。

在比特币中产生一个账户只需自己生成一对公钥和私钥，公钥可以公开，私钥需要自己保存且不能泄露，一旦泄露则意味着你的比特币账户已经泄露。这个公私钥对主要用来签名，比如 `Alice` 转账5个 `BTC` 给 `Bob`，`Alice` 需要用私钥进行签名，让区块链全节点知道确实是 `Alice` 转账给了 `Bob`，且别人也无法冒名转走你账户的比特币，因为不知道你的私钥。

若某个人想转走你的比特币，因为不知道你的私钥，所以他就在本地大量的生成公私钥对，看生成公钥是否跟你的公钥相等，若相等则私钥也相等，这样就可以轻而易举的获取你的账户，理论上好像是可行的，而实际上是不可行的，若是256位哈希值，产生跟别人相同的公私钥对的概率是非常小的（估计比地球爆炸的概率还小）

生成比特币账户是随机的，为了防止比特币中账户的碰撞，在生成账户（公私钥对）时要有好的随机源。
